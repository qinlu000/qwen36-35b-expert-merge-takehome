# 数据配比与四项 benchmark 提分：可用经验及边界

2026-10-16，北京时间。本轮实际联网阅读一手论文、作者配方、数据卡与消融；只读方法和统计，不运行模型、任务或API，不使用正式测试答案选数据。下列均为作者报告，未独立复现。

当前决策依据是 [SFT预算重设计](sft_budget_redesign_20261016.md)：三专家各一次、同数据Mixed一次、AVG/TIES有限dev比较。旧6M/15M不作为默认目标，本轮也不新增配比搜索分支。已有非思考64K/8K评测、清理显式teacher think等决定不变。

详细来源：[SWE专项](mixture_evidence_swe_20261016.md)、[Terminal专项](mixture_evidence_terminal_20261016.md)、[学术/科研专项](mixture_evidence_science_20261016.md)。

## 1. 核心结论

**有可参考经验，但没有找到可直接套用到本项目的“四项最优百分比”。** 较一致的可用经验包括：目标接口适配、监督过程质量、来源互补、现有模型的能力保留；许多公开百分比只是数据供给组成，没有做比例寻优。

需要区分三个问题：专家内部的来源/能力配比；三个专家之间的数据与训练计算分配；合版的参数系数。这三者不是同一个比例。四项分数等权，不自动推出四类训练数据各25%；AVG系数相同，也不表示各专家接受了等量有效监督或对结果贡献相同。

## 2. 最值得参考的实证

| 目标/问题 | 一手实验 | 对我们有用的结论 | 不能直接照搬的地方 |
| --- | --- | --- | --- |
| SWE Pro：质量还是数量 | [SWE-Prime](https://arxiv.org/html/2608.27449v1)：Qwen3-Coder-30B-A3B，全成功池31.05；随机10%27.22；精选10%30.92；精选＋片段mask34.75 | 选择有价值过程、保留状态、抑制空转监督；随机减量可能更差 | Pro public731，非V2 HARD51；最终是选样＋mask复合干预，非证明10%最优；未证等训练token/步数 |
| SWE：harness一致性 | [Orchard表10](https://arxiv.org/html/2605.15040v1)：mini训练模型在mini Verified57.9，换OpenHands19.0；OpenHands训练在OpenHands评测53.5，换mini为28.0 | 同接口的可执行动作/观察/结束语义，优先于照搬来源比例 | 这里是Verified500、Thinking模型、64K训练/128K评测；无本项目同版本验证 |
| Terminal：多样性与失败过滤 | [Nemotron-Terminal](https://arxiv.org/html/2602.21193v1)：synthetic全量264K条TB2=12.4；成功83K条=5.06 | 不把中途报错和有效恢复全部删掉；重视多技能操作 | 数据量与2epoch曝光不同；没有证明失败应占某个比例 |
| Terminal：当前强基座未必吃旧数据 | [TMax表7](https://arxiv.org/html/2606.23321v1)：Qwen3.5-9B TB-Lite41.9→large-SFT31.3；TB2.1为16.1→16.9 | 旧SFT大混池不保证现代模型提升；来源/监督质量先于体量 | mini式persistent shell、TB2.1及不同thinking设置；不能说TB2.1也明显下降，更不能当Qwen3.6退化定论 |
| HLE数学：来源互补 | [Nemotron-Math §4.1表4](https://arxiv.org/html/2512.15489v1)：总problem-solution数量不变，AoPS-only→AoPS/StackExchange-Math各半；high无Python HLE-Math12.22→13.60，有Python22.54→24.67 | 竞赛数学以外的社区型/开放问题，可改善数学题型覆盖 | 50:50按example，不是token最优；976道纯文本数学、长推理120K，非全2500图文或本项目非思考8K；不是Terminal/ASI比例 |
| HLE：邻近数学指标不能替代目标 | [OpenThoughts](https://arxiv.org/html/2506.04178v2)：最终850K数学/250K代码/100K科学；Qwen2.5-7B-Instruct起点HLE MCQ12.7，最终10.2，尽管其他推理指标改善 | 不应从AIME/GPQA提升推出HLE提升；保留多学科、模态与开放答案覆盖 | 512道text-only MCQ，不是全HLE；论文没有证明该约71/21/8记录配比最优 |
| ASI：直接提分证据仍缺 | [D3-Gym](https://arxiv.org/html/2604.27977v1)研究完整科学程序、执行产物与验证，在ScienceAgentBench评测 | 科研程序应作为独立内容桶，不能以普通数学QA/终端操作替代 | 本轮未找到当前ASI direct_llm、Qwen3.6、同协议SFT配比消融；邻近benchmark结果不叫ASI收益 |

## 3. 一般SFT配比研究能提供什么

[Data Mixing Optimization for SFT](https://arxiv.org/html/2508.11953v1)在instruction-following/math/code、Qwen2.5与Llama小模型、5M/20M/200M预算上研究数据权重。关键发现是较优比例随模型和数据预算变化；目标是验证loss，不能直接当工具任务成功率的最优比例。它需要多次小规模训练拟合，不适合在本窗口照抄整套搜索；可借“不存在一组脱离基座和预算的通用比例”的结论。

[Tülu3 §4.2表9](https://arxiv.org/html/2411.15124v1)的SFT消融中，去数学数据使MATH31.5→23.5，去Persona数据使IFEval72.8→53.6；去WildChat也影响多数分项。它支持能力定向数据和部分通用能力保留，但删除数据同时改变训练量，不能推出某个70/20/10最优，更不能用MATH/HumanEval代替HLE/SWE Pro。

实际可借的流程是：先发现技能缺口，审计合格来源，再补相关数据，同时检查原有能力。当前只允许预定独立task-dev的聚合诊断；不采用论文中无限次配比迭代，也不通过正式Base成败调数据。

## 4. 先说清“配比”按什么计量

至少同时记录四个量：去重任务数N、每任务一次的完整序列长度L、切窗/epoch后的实际processed token P、真正参与loss的新增assistant token S。公开记录比例不自动等于计算比例或监督比例。

按本项目[旧来源清理后长度均值](trajectory_lengths.md)，若修复、终端、D3科研、OpenR1数学四桶取相同记录数，则完整序列token约为：

| 桶 | 旧来源均长 | 等记录数下token份额 |
| --- | ---: | ---: |
| 修复（来源成功子集） | 31,174 | 64.6% |
| 终端 | 13,145 | 27.2% |
| 科研程序 | 3,291 | 6.8% |
| 数学QA | 673 | 1.4% |

这是算术情景，不是推荐比例；数学子池不代表广域HLE池，新教师长度也未测。工具观察消耗计算但通常不参与loss，不能从这个表直接推梯度权重。显式teacher think清理后，各来源的P与S变化不同，论文保留长CoT时的比例需重新核算。

## 5. 对当前三专家的实际建议

| 对象 | 应优先控制的配比维度 | 目前可做的决定 |
| --- | --- | --- |
| 仓库修复专家 | 原生mini/其他接口；语言生态；定位/修改/验证/恢复；任务家族与短中长历史 | 合格mini优先，覆盖所需语言和行为；限制同题多rollout挤占，不只挑最短或最难题；不直接套Orchard来源百分比 |
| 交互执行专家 | Terminal操作类别、科研程序/产物、必要协议行为 | 终端/科研两桶分开列合格覆盖和N/P/S/成本；本轮没有Terminal:ASI=70:30等直接证据，两桶不得相互冒充 |
| 学术推理专家 | 数学与其他学科；竞赛/开放题；文本/图像；有过程/仅答案 | 数学来源避免只有AoPS；社区数学可作互补。HLE数学40.84%和图像13.68%是公开评测分布，可指导dev覆盖，不是训练最佳百分比；保留其他学科与视觉缺口说明 |
| Mixed对照 | 与专家的数据曝光一致性 | 使用三个专家相同窗口multiset、出现次数及mask，不另加一套更大的通用池；实际记录各域P/S而非只写“均匀混合” |

共同基础/格式数据只有在观察到相应独立dev缺口、且有合格供给时才纳入原预算；Tülu/Agent类研究不是给当前已有强后训练模型机械加20%通用聊天的依据。最终配额按合格供给、主要覆盖、一次有限独立dev诊断及实际训练成本收敛，不增加新的数据量或比例训练分支。

## 6. 这些“经验”不能当成提分承诺

- 成功/失败、来源、语言和难度消融常同时改变样本数、长度、步骤及模型曝光，不能只看分差推一个因果比例。
- SFT、RL、更多推理token、不同工具权限、不同judge/harness的收益应分开；不能把最终RL模型的榜分写成SFT配比收益。
- 我们清理显式teacher think、采用非思考与8K单次输出；若清理后只剩答案，原长CoT推理收益不保证保留。不能只调整来源比例而跳过监督内容验收。
- 正式SWE Pro HARD51、TB2受限资源、HLE全图文、ASI完整条件的收益仍需本项目冻结后实测；不以论文或邻近benchmark分数替代。

本轮能支持的是有来源的选样优先级与可审计配比口径，不支持现在宣称找到最优百分比或保证提分。
