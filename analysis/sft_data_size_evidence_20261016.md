# SFT 数据量的一手证据（2026-10-16）

没有文献支持“四个专家各 2,000 条”是统一最低门槛；它可以是实验预算目标，是否足够取决于初始模型、任务覆盖、数据质量与留出集成绩。以下数值来自原论文或作者数据卡，不能直接迁移为 Qwen3.6 LoRA rank16 的保证。

- **LIMA：1,000 条。** 对 LLaMA-65B 用精挑的指令回答做 SFT，获得较强对话表现，支持“已有能力可以通过少量数据被激活”；并未证明千条能学会新的复杂领域知识或长程工具使用。[论文](https://arxiv.org/abs/2305.11206)
- **AlpaGasus：9,000 / 52,000 条。** 从 Alpaca 52k 中筛选 9k，高于使用全部数据的原版 Alpaca，说明质量筛选可以超过单纯加量；这不是所有分布上“越少越好”的规律。[论文](https://arxiv.org/abs/2307.08701)
- **Long Is More：1,000 条。** 从 Alpaca-52k、Evol-Instruct-70k 选最长回答，在多种 7B/13B 模型上取得较强结果。提示一条的长度与可学习内容会显著影响“条数”的含义；长回答基线也不能代替执行正确性验证。[ICML 原文](https://proceedings.mlr.press/v235/zhao24b.html)
- **SWE-smith：500 与 5,016 条成功轨迹。** Qwen2.5-Coder-Instruct-32B 用 500 条的对照达到 SWE-bench Verified 28.2%；主模型用 5,016 条达到 40.2%，但教师与数据构成也有差异，不能将分差全归因于数量。固定 700 条时，覆盖更多仓库仍改善泛化。它比通用对话 SFT 更接近本项目的 SWE/Terminal。[论文 §4、§4.1](https://arxiv.org/html/2504.21798v1)
- **Tülu 3：约 94 万条。** 官方数据卡标注 939,344 条（页面当前行数 939,343）；覆盖数学、代码、多语言等多技能，论文的分层子集实验中完整混合整体最好。这说明广覆盖目标仍可能从规模受益，不能用 LIMA 否定规模。[数据卡](https://huggingface.co/datasets/allenai/tulu-3-sft-mixture)；[论文 §4.3.1](https://arxiv.org/html/2411.15124v3)

计量必须分开：独立任务/完整轨迹数决定覆盖；输入总 token 主要影响计算；实际参与 loss 的 assistant token 才是监督量；epoch 增加重复曝光，不增加独立任务。项目现有 SWE448、Terminal374 虽然条数小，但长轨迹已有千万级总 token；不能据此断言监督 token 同样多，也不能把切片、复制或多跑 epoch 算成新增独立样本。建议先用相同留出集比较现有集与扩充集，再决定是否追到每专家 2,000 条（项目推断）。

## 对本项目的判断与2000条情景

先前448/374/500/82是当前数据供给和时间约束下的规模，没有证据表明它们已足以形成四个稳定专家。2000条独立高质量任务可作为扩量目标，不是通用最低门槛，也不保证收益。

| 专家 | 当前train | 完整序列token | 判断 |
|---|---:|---:|---|
| SWE | 448 | 约15.62M（native） | 可优先争取2000，增加仓库和任务类型覆盖 |
| Terminal | 374 | 约18.73M（缓存完整长度） | 已有较大算量；扩独立任务，不能将同题多轨迹算新任务 |
| HLE | 500 | 0.243M | 优先扩大到1000–2000，同时提高难度与答案质量 |
| ASI | 82 | 本轮未重复计token | 最薄弱；需要补充独立科研程序来源，不能复制凑2000 |

[TerminalHorizon官方数据卡](https://huggingface.co/datasets/shunzou05/TerminalHorizon-3K)明确2852条轨迹对应1535个环境；仅这个来源不能提供2000个独立任务，更需留出val和排正式同源。[ScienceAgentBench](https://huggingface.co/datasets/osunlp/ScienceAgentBench)仅102题，当前82/20按仓库拆分；要达到2000必须引入新任务来源。

**算量情景，不是排期承诺：**若新增样本保持当前平均长度，SWE 2000条约69.7M完整token，Terminal约100.2M；仅两者及Mixed内对应数据的一遍训练合计约340M token，另加HLE/ASI、验证、padding。HLE若保持现有长度和单卡配方，按500条43分34秒线性粗推，2000条约3小时，不能套给长代理轨迹。当前64K长序列尚无成功optimizer吞吐，不能可靠承诺SWE/Terminal的小时数。

本次只调研和提出扩量建议，尚未改为2000条或重复采样。用户此前明确的数据完整性、64K/8K预算及不得自行缩减要求继续保留；若扩大某专家，Mixed必须同步采用相同新并集。HLE现有500条的验证loss后期升高，也说明不能仅凭数量推断质量或效果。
