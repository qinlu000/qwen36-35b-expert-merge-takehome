# Open-SWE 实际轨迹长度：固定tokenizer分层抽样

2026-10-16实测完成：**39分片各均匀128条，共4,992条、291,470个assistant turns**，8个CPU worker运行91.35秒；没有执行轨迹命令、模型、API或GPU。全量95,291条仅有结构/标签元数据、没有现成长度字段；按测速全量约半小时，本轮未强行全量分词。

**clean整轨迹中位33,418 tokens，p95 59,429；源成功标签子集中位29,804，p95 51,814。**≤32K分别47.83%/61.51%，≤64K分别97.30%/98.89%。这是训练轨迹分布，不是正式SWE Pro V2任务的预算消融。

## 口径

- 固定Open-SWE revision `1db674173119d71df45c22007af99e214600711a`，mini/Qwen3.6两源。39片均匀取含两端的128行；每条按该分片N/128加权，mean、quantiles和覆盖率均加权。抽样是确定性等距分层，**不是随机抽样置信区间**；max只指样本观察到的最大值，不能称全库最大值。
- 固定Qwen3.6-35B-A3B tokenizer与chat template revision `995ad96eacd98c81ed38be0c5b274b04031597b0`；完整渲染system/user/assistant/tool、工具定义、bash XML参数及模板边界，关闭padding/truncation。raw显式preserve_thinking=true；clean移除assistant reasoning_content及balanced leading think块后preserve=false，保留普通解释文字、工具参数和真实观察。
- 4,992条中97条有非空reasoning_content，**没有assistant content think tags**，所以两口径接近。清理规则收紧为仅balanced leading块不会改变本次数字；不是把自然语言推理强行猜删。
- assistant output按渲染body计，**含bash tool_calls XML/command及结束token、不含role header**；它不是实测HTTP output usage，也不等于已确定的SFT loss mask。已用同一合成对话raw/clean验证标记移除后的渲染逐字等于原模板、Tokenizer backend IDs等于AutoTokenizer。
- 现有全量元数据审计：resolved=1有32,231条、0有53,622、-1有9,438；本次长度样本resolved=1为1,693条、88,092 turns。源resolved=1只是元数据标签，不代表最终质量、许可或去污染通过。样本加权成功人数约32,276.9只是估计，不能替代32,231这个真实元数据计数。
- 整轨迹是**未摘要的完整静态拼接长度**，不是累加每次API的prompt tokens，更不是已经测到的每turn输入峰值；源运行时是否隐藏截断/压缩不能由该长度反推。没有做窗口切片或补造摘要。

这些仅是“整条拼接序列再留一段输出”的**足够条件**：末次实际输出已经包含在整轨迹里，再预留会重复计算，故是保守界，不是精确每请求prefix峰值。≤32K整轨迹不能直接当成“32K服务且每次还能预留4K”的实际覆盖；同样，超过这些界也不证明每一步都超预算。
