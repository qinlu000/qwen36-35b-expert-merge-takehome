# SFT 数据规模与训练预算重设计

2026-10-16。针对用户要求重新设计，替代旧6M、15M及固定任务数作为默认训练目标的做法。本稿是待讨论的执行设计，不是已经测得的资源配额；本轮不下载、选题、清洗导出或启动训练。M=1,000,000 tokens。

## 1. 保留实验问题，取消先定数据总量

- 固定Base、三专家（仓库修复／交互执行／学术推理）、ms-swift LoRA SFT与静态合版主线。
- 主体只训练四次：三个专家分别从Base训练一次；Mixed从Base用三个专家数据的同一并集训练一次。AVG/TIES在独立dev比较，不再增加多档数据量、epoch、rank或学习率搜索。
- 一遍数据为起点。三专家分别看各自数据一次，Mixed对同一窗口与监督目标各看一次；不为凑更新步数重复小池。各分支独立优化器、batch尾部造成的更新数差异须报告。
- 训练rank、alpha、目标模块、窗口、batch与优化器尚未冻结；本稿不将旧r16/8K草案视为确认。评测64K/单次输出8K不决定训练窗口。
- 最终数据量是合格任务供给、覆盖和实测训练成本共同约束的结果。15M只保留为历史比较情景，不再作为必须达到或优先逼近的目标。

## 2. 先给必交结果预留资源，再算训练可用时段

硬截止仍为10月18日14:20，北京时间；最后12小时留整理与交付，核心实验目标止于10月18日02:20。不能把此前假设的“训练8小时”当已经落实的配额。

按当前最低正式评测范围，Base＋最终合版各四项、专家各目标项：SWE 51×3=153，Terminal 89×5×3=1,335，HLE 2,500×3=7,500，ASI 60×4×3=720，共9,708次任务尝试，另计dev、环境验证、fresh replay及判分。次数不等于等成本任务，也不能用单题timeout当平均时间。

先用独立任务的原生链路与固定并发获取端到端时长、模型等待、长尾、初始化与评分成本，再给余下正式评测／dev选模／导出上传排时段。正式Base运维耗时也可用于更新排期，但其逐题结果不进入训练选择。CPU数据准备、评分可与GPU工作重叠；四卡训练与当前模型服务按分时排，不假设未经验证的2卡训练＋2卡推理或双TP2能同时工作。

剩下可落实的四卡训练组时段记为H_train；Slurm排队与资源不可用会占截止前墙钟，须从可落实时段扣除，不能当GPU已经到手。若最低评测矩阵在当前资源下仍无法排下，应记录并解决资源／排期缺口，不能靠训练数据预算掩盖，也不静默减少正式次数、任务或改split。

## 3. 不用GPU即可先完成的数据审计

先跨新旧教师按PR／原题／模板／科研来源家族联合归组，排正式评测及其同源，留出val-loss和task-dev；余下才是train候选。训练轨迹有源success不意味着其任务可以重跑：可执行task-dev另需初态、输入依赖及独立验证器。

| 内容桶 | 覆盖依据 | 主候选与首要检查 |
| --- | --- | --- |
| 仓库修复 | 独立仓库的语言生态、修复动作及短中长历史；不把SWE统一debugging标签当细粒度bug分布 | mini/Qwen3.8-Flash-Next优先；核工具格式、工作目录／环境、源resolved与新清后长度 |
| 终端操作 | TB公开16类及难度；先保留主要类别，记录长尾缺口 | 已知Terminus2来源；任务／模板关联与结束／成功依据，不能只看task_complete |
| 科研程序 | ASI公开11域与程序、文件产物行为；四条件不算四个独立任务 | D3等可恢复来源候选；优先检查原任务映射、程序产物与执行筛选依据，新Science工具轨迹不直接替代 |
| 学术推理 | HLE公开8类、模态与答案形式；数学不能淹没其余学科 | Math-v4无工具CoT、Science-v2合格教师／无工具子集；删think后监督是否仍有解题内容，文本池不冒称覆盖图像／人文学科 |

每条合格候选最少记录：固定source revision／文件行ID、任务族、目标类别、teacher／harness／环境依据、许可、成功或答案核验依据、正式同源排除状态、清后完整长度L、最终labels监督量S、必要状态完整性。训练窗口确定后补窗口数、窗口后非padding token P、历史重复量与padding。

监督密度S/P只作成本与数据形态诊断，不作为统一淘汰阈值：SWE工具观察长但必要，不能只按密度挑短QA。若数学删think后只剩最终答案，应标记为答案／格式监督，不能继续当完整推理过程；是否保留由本轮学习目标与覆盖判断，而非教师名气决定。

先分片小审计结构与清理长度，不必全库分词／下载。SWE两个来源各一片仅作结构诊断；正式选样需覆盖分片／来源索引后分层，不能把文件前缀当全库随机样本。Science大JSONL先检查可筛字段与合格比例，再决定值得扫描的范围。记录扫描范围与遗漏。

## 4. 一次训练诊断，验证成本而不是搜索模型

在rank、窗口等训练配置讨论确定后，安排一次独立诊断作业：先用自造消息检查loader、mask、反向与保存重载；在同一初始化中测最终处理后的真实代表窗口。覆盖短QA、科研程序、中等终端、长SWE和最长允许窗口，按各域实际长度层取代表，使用正式拟用的batch、梯度累积和packing设置。

记录加载／首次编译warmup、稳定完整optimizer-step耗时及波动、每卡峰值显存、每步非padding／padding／监督tokens、保存重载和导出耗时。Mixed还需测接近最终来源与长度调度的混合batch；若配方变化影响batch成本，在同一诊断中补受影响部分，不把各域最快token/s平均后外推。

诊断adapter丢弃，不将该作业包装成有效训练或额外数据规模pilot。2步短样例只能证明能反向，不能证明长SWE吞吐；vLLM推理验收亦不能代替训练。具体计时步数以warmup后能观察稳定完整更新为准，诊断作业本身计入训练资源账。诊断启动前在H_train内另设墙钟上限，超限未取得稳定测量就记录未验收，不无界延长。

## 5. 用实际批次耗时反推能容纳的数据

令桶i的最终窗口非padding token为P_i，专家和Mixed对应整组训练吞吐为v_i、v_i^M。粗算条件为：

`T_诊断 + Σ_i(P_i/v_i + P_i/v_i^M) + T_各次初始化/验证/保存/导出/合版 <= H_train`

式中时间统一按秒、v按整组非padding token/s，排期展示时再换成小时。GPU小时另按每个实际分配作业的GPU数×占用小时求和，排队不计GPU小时但占截止前墙钟。

v必须来自相同模型／长度层／mask／batch设置的训练实测，并选择能覆盖观测波动的耗时估计。正式排期优先使用“最终批次计划的完整更新耗时求和”，因padding、长短混排、梯度累积及分支尾批不一定能由一个token/s解释。不能以30M除统一吞吐作完成承诺。

分别保存四本账：独立任务数N；每任务只计一次的清后完整序列token L；实际窗口和重复历史后的processed token P（另列padding）；真正参与loss的监督token S。专家与Mixed同数据合计约2P，不能把2P说成两倍独立数据。

## 6. 选样采用先覆盖、再扩展的单份清单

1. 先从每个合格主要类别选来源清楚、行为完整的代表任务，形成覆盖骨架。该步骤是覆盖检查，不宣称每类一题足以训练；没有合格供给则明确留缺，不用低质量数据填格。
2. 在候选池内按来源、语言／学科、任务行为与长度层分层；每任务族先留一条代表轨迹。保留固定seed、选入理由与扫描范围，避免同题多teacher或多窗口冒充多样性。
3. 在覆盖骨架之上增加独立任务；类别优先级只允许结合一次预定的Base独立dev聚合诊断与公开任务分布调整，在SFT前冻结。正式Base失败题不参与。暂不宣布四桶必须等token、等时长或按任意固定比例分配。
4. 将嵌套候选清单按实测批次成本代入资源约束，冻结一份实际能完成的规模。若骨架本身超预算，先讨论长轨迹窗口／覆盖取舍并重新计价，不能悄悄只剩最短易题。
5. 专家取该最终清单各自分区，Mixed使用完全相同窗口multiset、出现次数与监督mask；数据变化同时作用于二者。只做一版正式数据规模，不为寻找最好token数追加训练分支。

长SWE优先完整轨迹。若完整序列超训练可承受窗口，先核查能否按真实交互边界形成含必要状态的合法窗口；历史作上下文时mask，新增目标只监督一次。依赖无法保留则暂不纳入并记录覆盖缺口，不机械截尾、不编造摘要／动作或重放未验证环境。长轨迹策略未过验收前不冻结最终数据量。

## 7. 训练监控、止损和对照范围

保留既有最多中／末两个预定val-loss检查点，关注数值、格式及过拟合；不额外跑多个训练规模。最终checkpoint规则、val-loss各桶预算、task-dev任务清单与候选数在正式SFT前冻结；旧70题、100K val-loss及3h dev均是尚待验收的方案，不自动继承为确定事实。

主对照仍为同数据Mixed与两个合版候选AVG/TIES，采用同一独立task-dev的冻结协议；四域分项报告，小dev的一题之差不解释为可靠最优配比。不根据正式测试收益扩大训练或反复挑合版。

- 结构、来源家族或清理后状态不合格：隔离相关候选，不用重复epoch补量。
- 最终配置OOM或长轨迹不可合法装入：解决窗口／batch可行性后重计相关成本，不按短样例通过宣称ready。
- 预计四次主体训练超时：正式启动前同时缩小共同manifest，保留已定评测／交付时段；若启动后发生意外，使用可恢复checkpoint并明确记录曝光差异，不把不等量对照称为完全公平。
- 小val无明确收益或近似持平：按预定简单规则选择，不启动追加数据量／配比搜索。本项目报告的是一个受限规模实验，不声称找到了最佳数据量。
