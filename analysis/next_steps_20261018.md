# 资源允许后的优化方案

更新时间：2026-10-18（Asia/Shanghai）。以下是题目要求的后续研究方向和本轮没有执行的原因，不是已经完成的实验结果。

## 1. 重新构造数据，保持训推一致

当前训练轨迹和正式 benchmark 的环境仍存在差异，例如 system prompt、工具 schema、工作目录、依赖供给、网络策略和结束动作。下一轮应直接围绕目标 benchmark harness 重建或筛选轨迹：保存同版本的 prompt、工具调用、观察格式、工作目录和依赖快照；只保留能够在相同 sandbox 中完整回放并产生最终交付物的样本；用独立开发任务测量准备失败率、交付正确率、任务成功率、准备时间和成本。

## 2. 提高数据量

当前每个专家约 2,000 条训练样本，受时间和训练显存限制只跑一轮。后续应扩充高质量完整轨迹，保持来源隔离、去重和 benchmark contamination 检查；同时固定模型、LoRA 配方、训练 token、步数和数据配比，比较当前规模与更大规模的任务成功率，而不是只比较 loss。需要单独记录新增任务数、重复曝光次数、有效监督 token、训练时间、GPU-hours 和成本。

## 3. 调试合版方法

当前 AVG64 是冻结的等权 adapter delta 合版，AVG16 只是压缩对照，TIES-Dense 只有 HLE 对照，不能据此宣称完成四项合版方法比较。后续应在预先固定的独立开发集上比较 AVG64、等容量 Mixed、TIES-Dense 或其他明确配方，控制 rank/容量、训练数据和推理协议，分析参数冲突、容量差异、各域退化及推理成本；选择后再冻结配方并运行四项完整评测。

## 本轮未执行原因

以上三项均需要新增数据准备、训练、沙箱评测或 Judge API 调用。本项目剩余时间、可用 GPU/CPU 沙箱和 API 额度极度有限，因此只完成一轮 BF16 LoRA SFT 和固定合版/主要评测，没有把计划中的后续优化伪装成结果。
