# 按 benchmark 任务类型选择新数据：讨论方案

2026-10-16。用户要求先给方案，本轮停止继续下载、分类与选样。已有新候选清单仅为储备，不是最终 train/val。

> 最新澄清：用户确定每个benchmark各100个val任务，共400个；train每项约500是当前讨论目标，共约2000。此前合计100题的分配已失效。最终训练是否全用500仍待质量/类型供给与真实吞吐核算。

## 主线

先定义类型与目标分布，再挑独立 val，排除其全部同源任务后从新池选 train。最终 val 数量按评测成本确定，不机械使用全库10%；先前90/10仅为候选保留方案。

## 类型与比例

- SWE：语言/项目生态为主分层，功能模块与修复类型为辅助覆盖；官方统一debugging标签不足以表达细分。先固定通用分类规则，再核目标51任务的公共元数据；若仍不足，仅对公开题目说明作粗分类，不读取答案、参考补丁、隐藏测试或正式反馈。标注结果需注明人工类别而非官方标签。项目生态不冒充具体补丁语言。
- Terminal：官方16任务类为主，难度为辅助。
- ASI：11学科及程序/文件产物行为；同项目4条件仍是一任务族。
- HLE：8学科为主，图像/文本和答案形式为辅助；当前Math/Science四学科缺口不可用数学替代。

SWE当前9436个候选仅是此前按`resolved=1`且`category=bug-fix`预筛得到的修复子池，不是最终SWE全部候选的类型边界。`resolved`是发布方成功标签，`bug-fix`是来源任务类别，两者不能混同。目标统一`debugging`粗标签不足以证明源`feature-request/enhancement/other`都应排除；这些原始记录保留，待目标和来源按同一细分类核对后决定配额与逐条质量/环境验收。当前不假定最终全部是bug-fix，也不按源全库类别比例直接混入其他任务。

每类比例p=该类benchmark任务数/总任务数。给定最终子集大小N，按最大余数法将N*p转为整数配额。小val先确保主要类别；若需要全部类别覆盖，TB至少16、ASI至少11任务，仅为数学上的覆盖下限，不是充分统计样本量。稀有类超采或缺失均单列，不能声称小val精确复制全分布。

## 从新数据选择

优先新SWE FlashNext、Math-v4及Science-v2强教师子集；新Terminal/科学程序来源分别核质量、环境和契约，旧池只作跨教师关联与备选。候选同时标相同类型体系、来源依据、teacher、协议/环境状态、长度层与监督形式。缺类优先补同类新源，无法补齐时明确限制诊断范围。

先选val：从独立仓库/原题/模板/科研来源族选择，有金标准或可恢复验证器者才进入任务级val。只有教师轨迹的记录可作隔离val-loss，不能冒充任务成功率验证集。先按任务家族联合分组再留val，整族禁止进train。

再选train：先按目标类型比例建立一版配方，在每类内优先完整、质量依据充分、环境/工具相近的新轨迹；每族先一条。允许依据一次预定Base独立val聚合诊断作有限调整，并在训练前冻结。正式Base逐题成败不进入配方选择。

训练总量仍由最终窗口与真实训练吞吐确定，候选池大不意味着全训。小val不硬造语言×修复类型×长度的全交叉格；先满足主分层比例，再检查辅助覆盖。

## 历史方案：曾按合计100题val理解

用户确定val用100题；本稿暂按四项合计100个独立任务理解，每项内部匹配目标类型比例。建议val分配SWE20、Terminal20、ASI20、HLE40；这是待讨论的分配，并非用户已确认各项配额。跨项不按原始benchmark题数分配，避免HLE数量主导；报告仍按四域分项与等权指标。ASI多条件、同任务多seed不增加独立题数。

首轮train建议约2000个去重任务，SWE200、Terminal200、ASI100、HLE1500，各一条代表轨迹、一遍数据；三专家分别看各自数据一次，Mixed同并集各看一次。此为覆盖驱动的采样目标，不是硬件测算、最低充分样本量或最优配比，不能据此承诺四卡训练时长/收益。

理由：工具任务一题含多轮动作/反馈，优先几百个独立任务的语言生态/操作覆盖；Terminal200按89题类分布可给1/89的长尾类约2条，而非无限扩大任务池。HLE以单次短问答为主、覆盖8学科，允许更多题目；1500下最少份额的Engineering约67题，主要类别可达百题，但这仍是工程选择，不是样本量理论。SWE按新两片成功bug-fix64条样本均长41801估计，200条约8.36M完整序列tokens；专家和Mixed该部分合计约16.72M，窗口重复、其余域及padding另计，真实训练吞吐尚未测量。

val100若按自然比例取整，Terminal/ASI长尾可能为0；如强求每类至少一题，需要显式超采并记录偏离，不能同时声称精确复制自然比例或依靠小val排细微名次。各项配额冻结前应在比例与长尾覆盖间选择。

新数据当前覆盖不足：EcoCoder只有31个Python候选家族且仅生态学；不能重复复制到ASI100。Math/Science仅覆盖HLE四个学科，Science无独立gold；缺失学科/图像及可判分依据必须先补来源或明确范围，不能用数学凑1500、不能把teacher答案称独立gold。目标配额不等于已有可用任务数。

最终正式训练清单在类型比例、供给与训练吞吐测量后锁定；超时应共同缩减专家/Mixed数据，不削弱对照。当前仅讨论数量，不继续下载/分类/选样或训练。

## 当前方案：每项100 val、约500 train

用户澄清每benchmark100个val，共400个独立任务；建议接受为固定val建设目标。train每项约500，共约2000任务，是用户提出的待讨论首轮目标，可以据此准备独立候选；尚不等于已证明能够全量训练或足以形成专长。

| 内容桶 | val独立任务 | train目标 |
| --- | ---: | ---: |
| SWE | 100 | 约500 |
| Terminal | 100 | 约500 |
| ASI | 100 | 约500 |
| HLE | 100 | 约500 |
| 合计 | 400 | 约2000 |

对应三专家数据目标：仓库修复500、交互执行1000（Terminal500＋ASI500）、学术推理500；Mixed用同一2000任务并集一遍。不同工具回合/teacher rollout/ASI条件/seed不能冒充新增独立任务。若500全部入train，则每域需至少600个合格独立任务支撑train+val，并在分组时考虑模板/仓库/来源族关联。

每项val100足以作为受限开发比较集：TB16类按89题目标比例可保留每个1/89稀有类约1题；ASI11域也可覆盖但最小类约2题；HLE100可按8学科比例并安排约14图像题（包含在100内）。小切片仍稀疏；对独立二项成功/准确率，n=100在p=0.5处95%正态近似半宽约1.96*sqrt(0.25/100)=9.8个百分点，不能用1–2题差异声称稳定提升。程序评分等非二项指标不直接套此公式。

400任务不等于400调用。原比较矩阵若四个全域对象（Base/Mixed/AVG/TIES）各400，加三专家目标域共400，在每任务单次运行的起点下约2000次val任务尝试；多科研条件/多seed另计。训练中只作预定val-loss检查，真实执行集中在冻结的少数候选，不能每次保存都重跑全val。具体dev预算仍待冻结，不修改正式评测协议。

train四项各500并非等计算：新SWE两片成功bugfix64样本均长41801，500条粗估20.9M完整序列token，专家与Mixed该部分合计41.8M，尚未计切窗重复、padding、其他域和初始化保存；新Terminal实际长度仍待测。与旧200/200/100/1500方案总题数相同，但长交互任务占比增加，不能复用旧计算预算。真实训练吞吐决定最终入训数，必要时训练前共同缩小专家/Mixed的相同清单，并保留类别覆盖；不为了数量对称牺牲质量或强制重复epoch。

当前新源尚不满足每域600个可用任务：ASI生态Python仅31候选家族、缺多域与验证器；HLE四学科之外及图像缺源，Science gold仍待补。任务级val本身无需教师轨迹，但要有输入、金标准/验证器与环境；这些缺口属于后续数据建设，不能称已经完成400任务val。本轮仍只讨论数量，不恢复下载/分类/选样或训练。
