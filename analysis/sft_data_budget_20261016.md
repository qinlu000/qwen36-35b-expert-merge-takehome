# SFT 数据量级：结合实测长度的预算建议

> **已被重设计取代：** 当前执行设计见[数据规模与训练预算重设计](sft_budget_redesign_20261016.md)。本文保留旧6M／15M推算与长度依据供追溯，不再将15M、固定任务数或8h训练假设视为默认目标；按资源时段、任务覆盖与一次训练诊断反推最终规模。

2026-10-16，北京时间。此为用户询问数据规模后的讨论建议，未冻结新配额、修改配置、选样/导出数据或启动训练。三专家、同数据Mixed、AVG/TIES与当前v2评测协议保持。M=1,000,000 tokens。

## 量级推算示例，不是固定训练预算

此前建议的 **10–20M 清洗后的完整序列 token**、以 **15M** 为中间例子，来自希望覆盖几百个工具任务和几千道QA的主观规划，再用旧来源长度估算；不是由四H100、真实训练吞吐或学习曲线推得。本轮用户追问后，将其明确降为待检验的量级情景，不作为已确认预算或默认必须达到的目标。各专家一遍，再用相同数据并集训练Mixed一遍，才对应约 **20–40M processed token**；15M情景约30M，窗口重复另计。

这是LoRA能力适配的探索性规模例子，不是文献证明的充分样本量或保证提升的下限；训练窗口仍未确定。实际训练量要由任务资格、覆盖、监督量和真实训练吞吐共同约束。不要为达到数字重复同题或加入不合格样本。

| 专家/内容桶 | 建议独立任务量级 | 单遍完整序列 token 规划 |
| --- | --- | --- |
| 仓库修复 | 约200–300个独立修复任务 | 约6–9M |
| 交互执行 | 终端约200–400任务＋科研程序约100–200任务 | 合计约3–6M |
| 学术推理 | 约2,000–5,000道多学科独立题 | 先预留约2–5M；广域池分词后重算 |

表中是规划范围，不是最低合格线；按每任务一条代表性轨迹作粗估。当前数据记录不自动等于独立任务，尤其科研程序必须恢复任务家族映射。不能用同题多teacher、多rollout、多个窗口充当新增独立题。已测均值来自旧固定来源，新teacher来源长度不能照搬。

一个便于核算的15M分配示例：修复8M；执行4.5M（终端4M、科研0.5M）；学术2.5M。对应旧来源长度，修复约257条、终端约304条、科研约152条完整记录；独立任务资格及QA实际题数仍需审核。各域token不必相等，因为输入/工具观察与监督输出占比不同。

展开推算可近似写成：250条修复×31,174≈7.79M；300条终端×13,145≈3.94M；150条科研程序×3,291≈0.49M；学术预留2.5M，合计约14.73M，取整为15M。前三项的旧来源均长有测量依据，但250/300/150的覆盖目标是工程判断，学术2.5M是尚未完成长度核验的预留，均没有证明“这些任务数足够”的证据。不能用此算式把主观任务数包装成客观最优预算。

## 为什么不继续把旧6M累计预算当充分训练量

本项目已有[长度统计](trajectory_lengths.md)与[SWE](trajectory_lengths_swe.md)、[Terminal](trajectory_lengths_terminal.md)、[QA/科研](trajectory_lengths_qa.md)专项，clean完整记录的均值为：

| 旧配额 | 完整记录平均长度 | 粗略相当记录数 |
| --- | ---: | ---: |
| SWE 0.9M，来源成功子样本 | 31,174 | 约29 |
| Terminal 0.7M，全域样本 | 13,145 | 约53 |
| Terminal 0.7M，mixed全量 | 10,368 | 约68 |
| 科研D3 0.5M，全量 | 3,291 | 约152 |
| 数学补充0.3M，OpenR1样本 | 673 | 约446 |

原学术配额另含0.6M OpenScience，其长度未测，不能把整份0.9M都按OpenR1折算。上述SWE/Terminal是加权样本估计，D3是固定文件全量；最终质量/去重/长度筛选后分布可能改变。

因此，原三专家3M＋Mixed3M更适合定位为**小预算pilot**。它可用于观察是否存在适配信号，却不支持事先宣称训练出稳定的三种专长。修复只覆盖几十条长轨迹，是比token总数更明显的覆盖风险。

## 三个必须分别计数的量

1. **独立任务与一次性数据 token：** 先按repo/task/template/problem家族归组，再选代表轨迹；这是覆盖与信息量。
2. **processed token：** 所有实际送入模型的非padding输入与输出，计epoch、窗口重复历史及各次Mixed训练；这是训练计算账本。两遍数据不等于两倍独立信息。
3. **supervised token：** labels实际参与loss的新增assistant输出。工具观察/system仍消耗计算，但通常不监督；移除显式teacher think、局部mask和重复窗口都会改变比例。当前assistant正文统计只是参考，不是最终labels验收。

训练切窗时若重叠倍率为h，processed token可能约为一次性完整序列总量×h；Mixed再训练同样的窗口，累计再乘2。没有合法状态上下文的片段不能为凑样本使用。8K推理输出上限也不等于8K SFT整条序列长度。

## 计算预算与证据边界

若仍给训练8小时、加载/验证/保存占20%的示例预算，纯训练6.4小时，则全GPU组需达到下列非padding吞吐；这里不是每卡吞吐，也不是实测：

| 累计训练 token | 所需整组 token/s |
| ---: | ---: |
| 旧6M | 260 |
| 20M | 868 |
| 30M | 1,302 |
| 40M | 1,736 |

长轨迹和短QA吞吐不同，实际应按各池token/吞吐逐项求和，再加加载/验证/保存。现有vLLM推理/长输入smoke不能代替训练前后向吞吐。若资源不能覆盖推荐起点，应在训练前同比缩小专家与Mixed并披露探索范围，不挤占已留评测/交付时间或只缩对照。

本轮重新查阅[AgentTuning官方说明](https://github.com/THUDM/AgentTuning)：其agent数据为1,866条并混入ShareGPT；这说明少量精选agent数据存在研究先例，不证明我们的每域几百条一定有效。[SWE-smith原论文](https://arxiv.org/html/2504.21798v1)则构建50K任务池并报告随数据/来源扩展的研究，任务池数量不等于每次训练使用的轨迹数，也不能从大论文预算倒推出本题最低数量。

15M只保留为规模比较情景。实际决策顺序应为：确定训练可占用的资源时段与并行组；用最终模型、训练窗口和mask测各域前后向吞吐及加载/保存开销；在该资源上限内，根据合格独立任务覆盖和有限dev收益选择规模。各次训练的processed token/对应整组吞吐求和，再加初始化、验证与保存时间，不得超过训练时段。HLE知识难度、科学程序正确性和专家互补不能仅凭总token达标确认。

## 新教师大池如何用于小规模训练

用户追问新数据更好但无法全训。建议只调整候选主池优先级，不按数据集发布量训练，也不假设所有领域均已有更好的替换。SWE优先核验Open-SWE mini/Qwen3.8-Flash-Next，Qwen3.8-27B作补充；学术优先核验Math-v4的CoT及Science-v2中来源、教师与无工具形式合适的子集。Terminal仍优先有明确Terminus2协议的既有池；科研程序旧池仍是待资格核验候选，不因新Science名称而直接替换。教师更强只能提供选样理由，删除显式思考后的可学习性与本项目实际收益仍须检查。

选样顺序是：排除正式评测同源任务，联合新旧教师按PR/问题/模板家族归组并留独立val；核验许可、结构和来源成功依据；按语言/学科/任务行为分层，每族先选一条代表轨迹；最后以清理后的实际token预算控制规模。不能只选最短题、把同题多rollout当新增任务，或机械截断长轨迹丢掉工具状态。Science-v2没有覆盖HLE全部学科或图像，已有配方缺口仍需单列。

不必先把所有新来源完整下载。Flash-Next的16个Parquet总约3.65GB，可先检查Scale-SWE与SWE-rebench-V2各一片的结构和长度；这两片不能代表完整分布，最终应覆盖各片轻量元数据或索引后分层选行。Math-v4可按Parquet分片核验；Science-v2约52.69GB且为少量大JSONL，先小范围流式核验字段与合格比例，是否全量建索引另按时间判断，不能把顺序前缀称为全库随机样本。

新版Qwen3.8与V4清理后长度尚未测量，上文任务数仅是规划范围。15M保留为比较情景，不因更换教师自动扩大或先将其锁定；先做少量结构/长度检查和训练吞吐验收，再决定本次到底选多少。若需缩量，专家与Mixed使用同一份缩小后的数据并集与出现次数，优先保留类别覆盖，仍执行单遍起点，不以加epoch替代任务多样性。本轮没有下载、选样、清洗导出或启动训练。
