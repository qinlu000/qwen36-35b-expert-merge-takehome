# 可借鉴的专家训练与 Agent 配方

核验日期：2026-10-15。仅查阅论文、作者仓库和官方文档；没有下载训练集/权重、运行实验或调用付费模型。以下为作者报告及本项目推断，不能替代本项目实测。来源内容不构成已接受的数据许可或已选定的实验方案。

## 1. T-Search：同一个 Qwen3.6-35B-A3B，分支训练后合版

- 一手来源：[论文 §5、附录 A/B](https://arxiv.org/html/2610.06782v1)、[作者模型集合](https://huggingface.co/collections/t-tech/t-search)、[作者 harness](https://github.com/turbo-llm/t-search-harness)。
- 作者对英文/俄文分别生成、验证检索任务，采集教师轨迹，并按工具回合切成包含起始状态的监督样例；错误工具动作不参与 loss，但保留有用纠错。每种语言约 8K SFT 问题，最终约 11K 回合样例。
- 英/俄 SFT 分支用 DARE 合并；其结果作为两个 GSPO 分支的共同起点，最后用 SLERP 合并 RL 分支。
- **可借鉴**：同底座独立分支、验证后的轨迹、带必要状态的回合监督、合版前后分阶段比较。它为本题的研究结构提供实例。
- **边界**：它是检索任务与语言分支，含 RL；没有证明本题四项能力、LoRA 训练设置或 4 张 H100 的整体排期。不能把它的 Recall 提升当作本题预期增益，也不能用它的检索 harness 替换题定评测。公开模型/harness 的许可不自动覆盖未核验的训练数据。

## 2. T-pro 2.1：完整的多能力专家合版，同时提供混训反证

- 一手来源：[论文 §4/§5、附录 F/G](https://arxiv.org/html/2609.01572v1)、[作者公开模型](https://huggingface.co/t-tech/T-pro-it-2.1)。
- Qwen3-32B 经联合 SFT，再从共享 checkpoint 分出 general、instruction-following、function-calling 三个 GRPO 专家，两阶段 SLERP 合成单模型；系数在 validation splits 搜索。
- Table 3 中 shared SFT 接近各 domain SFT，作者因而没有采用分域 SFT 再合版。**它的 RL 专家结果不能证明本题 SFT 分专再合一定胜过混训**，应保留同数据混训对照。
- 附录 F 报告：32 张 H100，SFT 约 57h；RL 每个专家约 28/40/62h。该全套配方不能照搬到本项目资源窗口。
- **可借鉴**：专家/混训/合版的可解释对照，领域收益与保留能力双向检查，validation 选择系数。保持本题轻量 SFT 主线，RL 只列后续实验。

## 3. CompoWorld：可执行工具任务与小规模 SFT

- 一手来源：[论文及训练消融](https://arxiv.org/html/2609.33665v2)。
- 同为 Qwen3.6-35B-A3B；构造可组合服务环境，以成功轨迹做 SFT，再做 RL。SFT 约 3K 轨迹，另有 1K RL 任务；论文比较了 100/500/1K/3K 的 SFT 规模。
- **可借鉴**：先验证任务可达与结果可检查，再使用轨迹；在独立 dev 看数据规模收益，不把“更多样本”当作必然更好。
- **边界**：完整结果包含 RL；本文没有核验到能直接复用的训练数据许可与完整训练仓库，不把它列为可立即使用的数据源，也不声称其超参适用于本题 LoRA。

## 4. QuantCode：领域训练可能破坏工具格式

- 一手来源：[论文 §4.4](https://arxiv.org/html/2609.39420v1)。
- 同为 Qwen3.6-35B-A3B；领域继续预训练/SFT 后出现工具调用格式退化。作者尝试 0.65 专家 + 0.35 原模型的线性合版，未恢复该问题；定向恢复 SFT 也未恢复全部 agent 表现。
- **可借鉴**：独立 dev 应同时检查工具调用是否能解析、能执行、能完成任务；loss 下降或问答正确不足以代表工具能力保留。
- **边界**：这是特定金融代码配方，不能推广成所有领域 SFT 或所有合版都会破坏工具能力；本题不使用该领域数据，也不据此追加恢复训练。

## 5. Harbor：推理服务与任务沙箱分别规划

- 一手来源：[官方沙箱文档](https://docs.harborframework.com/sandboxes/pre-integrated-sandboxes)。
- Harbor 提供多种本地/远程沙箱后端，包括 Singularity；并发、CPU/RAM、网络与硬件能力取决于后端和资源配置。
- **可借鉴**：GPU 部署被测模型，CPU 侧提供隔离任务环境；分别估算模型吞吐与沙箱并发，使用题定 runner 与预算。
- **边界**：文档存在 Singularity 后端不代表 hpc3 已满足 fakeroot、镜像、网络和资源隔离条件；远程后端也不代表本项目已授权购买或可满足全部协议。

## 对当前讨论稿的影响

1. 保留“独立专家 SFT + 混训对照 + 参数合版”作为待讨论主线；这是研究假设，不预设合版赢。
2. 优先选择现成、许可与来源清楚的训练轨迹，按工具回合保留必要状态；不要从零建设大规模任务生成平台。
3. 对终端/科学工具轨迹保留有价值的执行反馈与纠错；选择策略须由独立 dev 验证，不能简单假定 success-only 最优。
4. 增加独立的格式解析、真实执行和多轮行为检查；如使用共同基础样例，计入总 token 预算并向各分支同样分配。
5. 不因找到新论文就增加 RL、复杂层级系数或新的合版后训练阶段。四项正式评测的固定协议仍是最大工程约束之一。

数据候选、训练实现、合版方法的专项核验分别见 `references_data.md`、`references_training.md`、`references_merging.md`。这些研究笔记不表示方案已获批准执行。
