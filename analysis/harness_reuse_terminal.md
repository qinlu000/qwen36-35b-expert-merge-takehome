# Terminal：标准 harness 代码可直接复用

2026-10-16 只读核验。**可以直接用公开 Harbor/Terminus-2，不需要自己实现终端 agent。** NVIDIA 原始批量采集 launcher 是否公开，与标准 harness 有没有代码是两个问题；前者未确认，不影响复用后者。80 已有 Harbor 0.24.0、固定 commit `f527f8e447038fd242d08ecfa8aaa8029100da97`，Terminus2 类自报版本 2.0.0。

| 可复用部分 | 固定源码实际入口 | 我们需要做什么 |
| --- | --- | --- |
| agent 注册与主循环 | `AgentFactory` 注册 `terminus-2 → harbor.agents.terminus_2:Terminus2`；类负责多轮调用、解析反馈、完成确认、摘要和轨迹保存。[factory](https://github.com/harbor-framework/harbor/blob/f527f8e447038fd242d08ecfa8aaa8029100da97/src/harbor/agents/factory.py)、[Terminus2](https://github.com/harbor-framework/harbor/blob/f527f8e447038fd242d08ecfa8aaa8029100da97/src/harbor/agents/terminus_2/terminus_2.py) | 直接选内置 agent，固定原生参数；不重写 planner/loop。 |
| JSON 动作协议 | `TerminusJSONPlainParser` 解析 analysis/plan/commands[keystrokes,duration]/task_complete。[parser](https://github.com/harbor-framework/harbor/blob/f527f8e447038fd242d08ecfa8aaa8029100da97/src/harbor/agents/terminus_2/terminus_json_plain_parser.py) | 复用原 parser；训练整理保留其动作语义。先前九个独立合成解析检查已通过预期，不代表实际任务成功。 |
| 持续终端与观察 | `TmuxSession` 通过 `BaseEnvironment.exec` 发按键、保留 shell 状态并获取增量屏幕。[tmux](https://github.com/harbor-framework/harbor/blob/f527f8e447038fd242d08ecfa8aaa8029100da97/src/harbor/agents/terminus_2/tmux_session.py) | 直接复用；Docker/Apptainer 的容器启动由 environment 层承担。 |
| 对话历史 | `Chat` 记录 user/assistant；`interleaved_thinking` 决定是否把额外 reasoning_content 带回历史。[Chat](https://github.com/harbor-framework/harbor/blob/f527f8e447038fd242d08ecfa8aaa8029100da97/src/harbor/llms/chat.py) | 对接已确定的模型 thinking/template 设置；JSON 内 analysis/plan 仍保留。 |
| 本地 Qwen 接口 | Terminus2 默认 `_init_llm → LiteLLM`，原生参数含 model_name、api_base、model_info、llm_kwargs、llm_call_kwargs；LiteLLM 显式处理 hosted_vllm、自定义模型信息并调用 `acompletion`。[provider](https://github.com/harbor-framework/harbor/blob/f527f8e447038fd242d08ecfa8aaa8029100da97/src/harbor/llms/lite_llm.py) | 配置本地 vLLM 的 OpenAI-compatible endpoint、served model 名、context/output 信息和生成参数；不必编写 Qwen 专用 agent/provider。实际请求、thinking、top_k/seed 透传仍要 smoke。 |
| 官方 TB2 任务与判分 | `harbor run` 是 job start 别名，CLI 支持 `--dataset`、`--agent/-a`、`--model/-m`、`--ak`、`--env`；固定 registry 有 `terminal-bench@2.0`。[CLI](https://github.com/harbor-framework/harbor/blob/f527f8e447038fd242d08ecfa8aaa8029100da97/src/harbor/cli/jobs.py)、[registry](https://github.com/harbor-framework/harbor/blob/f527f8e447038fd242d08ecfa8aaa8029100da97/registry.json) | 直接复用正式任务/容器/验证器管线，按本题冻结的版本、完整89任务、资源和五次运行配置接线；无需另写评分器。 |

**Prompt 的一行差异不要求新写 agent。** 源 Corpus 通用模板把换行写成“Most bash commands…”，固定目标写成“You must end every command…”。原生 `parser_name` 可选择 JSON/XML，但模板路径是内置 `_get_prompt_template_path()`，没有独立自定义 system-prompt 参数。最简单的处理是正式 TB 保持固定官方 JSON 模板，所有模型一致；旧轨迹保留自身原始前缀并做必要格式整理。若以后明确要求逐字复刻源前缀，可单独固定模板小改/薄子类，但当前没有必要为了这一行改 agent。不能把“模板不是每字相同”说成“没有可复用 harness”。[固定 JSON 模板](https://github.com/harbor-framework/harbor/blob/f527f8e447038fd242d08ecfa8aaa8029100da97/src/harbor/agents/terminus_2/templates/terminus-json-plain.txt)

**环境构建方式相近，运行后端单独处理。** Nemotron 训练任务包与目标 TB 都提供 `task.toml + environment/Dockerfile + 文件资产` 的 Harbor 结构；源 mixed 的私有 latest 镜像有公开 Dockerfile 可作为重建入口，但重建后需锁本次 digest/依赖并恢复逐题 files，不冒称拿到了原教师同一镜像。目标任务各自的基础系统/构建内容不同，无需强行统一 Ubuntu。现有 Apptainer/SIF 后端替换只处理环境启动、输入初始化、权限/网络和资源，不需要替换 Terminus2/parser/tmux/Chat。后端能否满足题定隔离与配额是环境验收问题，**不是 agent harness 要重写**。[固定 Docker 后端](https://github.com/harbor-framework/harbor/blob/f527f8e447038fd242d08ecfa8aaa8029100da97/src/harbor/environments/docker/docker.py)、[固定 Singularity 后端](https://github.com/harbor-framework/harbor/blob/f527f8e447038fd242d08ecfa8aaa8029100da97/src/harbor/environments/singularity/singularity.py)

因此本项新增工程应限制为：**runner 配置与本地模型接线、任务环境构建/文件初始化、旧轨迹训练格式整理**。不需要引入 NeMo Gym 整套训练栈才能使用标准 Terminus-2。此前[动作/模板证据](harness_compatibility_terminal.md)、[sandbox 构建证据](trajectory_sandbox_terminal.md)继续适用。本轮未调用模型/API、执行任务、安装依赖或修改配置；代码可复用不等于本地 Qwen＋正式容器已完成端到端验收。
