## 结论

联网实证更新：见[四项上下文证据汇总](context_evidence_20261016.md)。依据查到的运行报告，**不再建议直接把统一32K作为所有项目的首选**：SWE64K为效率折中、128K更稳；Terminal32K/4K有低预算完整实跑；ASI direct32K/8K有本地官方初始文本输入容量依据；HLE32K仍需图文覆盖检查，8K输出较稳、4K是进一步压缩候选。下文32K表保留为用户提出的讨论档，并非已证明充分或已实施。

已下载训练轨迹的CPU实测另见[长度汇总](trajectory_lengths.md)：SWE来源成功子样本整条≤32K约61.51%、≤64K约98.89%，而Terminal全域clean样本≤32K约99.83%、mixed全量5689条均≤32K。单次assistant通常短，SWE主要需要历史空间。8K SFT不能直接整条装入多数工具轨迹，完整短轨迹筛选或保留状态的分段方案需要另定；这些是训练来源统计，不是正式benchmark需求分布或通过清洗的比例。

用户先提出统一32K，随后认可按实测为SWE保留更长窗口，并询问单次输出。当前建议SWE64K/8K、Terminal低预算32K/4K、ASI direct32K/8K、HLE32K/8K，见下表；尚未冻结执行。Terminal 的256K context / 80K max_tokens 是题面明确要求；32K Terminal属于资源受限协议，不能自行替代题定结果。4 H100 80GB 的低并发显存容量有可行依据，但长上下文请求、图像和各harness尚未全部实际验收，不能保证全量评测在剩余时间内完成。

这里 K=1024。上下文包含 system、工具定义、图片展开、任务、全部保留历史以及本次输出；不表示可送满输入再额外生成。每次输出上限不是整题累计输出上限，更不是每题必定生成这么多。

## 效率优先候选（当前讨论案）

| 项目 | 总context | 每次输出 | 解题总墙钟 | 当前建议依据 |
|---|---:|---:|---:|---|
| SWE / mini | 64K = 65536 | **8K = 8192** | 30min | 成功来源样本最长单次5011；8K全部容纳，避免4K截断少量大bash/patch动作 |
| ASI / direct_llm候选 | 32K = 32768 | **8K = 8192** | 20min | 一次完整程序；D3短代码不是所有ASI程序的长度上界 |
| HLE / 无工具 | 32K = 32768 | **8K = 8192** | 5min/题 | 保留可见解答与最终答案；没有当前非思考模型4K无损证据 |
| Terminal / 独立dev与消融 | 32K = 32768 | **4K = 4096** | 30min | 已测clean单次约99.8%≤4K；4CPU/8GiB资源受限协议 |
| Terminal / 题定正式结果 | 256K = 262144 | 80K = 81920 | 3h | 32CPU/48GiB、五seed保留；能否按时完成仍需吞吐依据 |

这套是用户强调效率后提出的具体可讨论预算，并非已测最优值或已实施配置。SWE用64K服务，其余资源受限运行用32K，题定TB另用原参数。SWE仍用原工具、初始环境、任务集、判分及fresh replay；30min是自选预算，区别50min locked protocol，不再声称完全遵循其原预算。

单次上限不是每次必须生成的数量：模型产生EOS便结束。SWE样本绝大多数动作远小于4K，但来源成功样本最大5011、4K会截断其中少量大写文件动作，所以当前保留8K而非仅为降低名义上限固定4K。此前全标签99.9749%≤4K是长度证据，不是所有任务正确执行的保证。Terminal4K也可能截断约0.2%的已测clean动作，独立dev需保留length原因及解析结果。

总context包括输出：SWE64K预留8K，实际prompt最多57344（56K）；Terminal32K预留4K，prompt最多28672（28K）；ASI/HLE32K预留8K，prompt最多24576（24K）。prompt含system、模板、工具定义、图片展开、题干和全部保留历史。不能保留80K输出同时将总context设为32K；也不能在HTTP失败后自动裁掉图像或题干。真实输出字段须传到服务验收，不把协议JSON当实际生效证据。

32K对长程工具任务更激进：mini没有原生history摘要，到上限会中止；额外加摘要会改变harness，不能当现成功能。Terminus有摘要但32K下会更频繁触发，主/辅助输出预留与原86,016阈值都需重新验收，不能沿用大窗口阈值。HLE没有工具历史，仍需核图像与完整题面实际token；ASI静态程序生成的输入空间相对明确，但8K程序截断风险仍在。先在独立dev核输入长度、工具历史触顶、length截断、成功率与延迟，再决定正式前是否全项32K或为某benchmark统一保留64K；不按正式失败题临时扩大窗口。

HLE 5min是每题生成、排队与传输重试共享的外层deadline，单次HTTP也须按剩余时间收紧，不能还容许一次HTTP独立等600s。它不表示每题平均5min，评分单独异步进行。ASI生成与执行共用20min，不是各给20min；SWE构建、fresh replay、verifier和评分另计，30min不能当完整端到端上界。

主要代价：较短输出可能截断程序或解题过程，较短历史可能使长任务失去上下文，较短超时可能减少修复与计算机会。缩短context上限本身不会使同样短请求更快；本轮更直接限制长输出和长尾时间，并通过预构建、低排队和有效batch提高吞吐。8K/4K仍是每次输出，不是整题累计输出，不能承诺总token或耗时按减半/1/4同比下降。

保留完整图片、官方题干、任务清单、harness动作/观察/结束契约。用独立dev记录length截断、context溢出、有效成功及耗时分布；按事先固定的统一预算验收后，在正式Base前择一冻结。同项全部模型一致；不根据正式分数或个别超时任务追加预算，也不把短预算Base和长预算合版作同协议提升比较。若以后允许Terminal资源受限结果替代题定配置，应取得面试方明确认可并记录，当前没有该认可。

训练维持8K序列起步、SFT主线；不增加16K/更多数据/在线RL分支。此处仅减少评测运行预算候选，不改变数据环境相似、公开harness复用与监督窗口的要求。

## 上一版128K候选（保留作对照）

| 项目 | 单请求输入＋输出总上限 | 单次输出上限 | 交互与时间 | CPU / RAM |
|---|---:|---:|---|---|
| SWE / mini | 128K = 131072 | 8K = 8192 | 保留官方工具、观察与结束契约；50min；不新增100步上限 | 原任务1 CPU / 4GiB；fresh replay另计 |
| Terminal / Terminus-2 | 256K = 262144 | 80K = 81920 | 题定3h；五seed；保留原生摘要，不额外砍轮数或累计输出 | 题定32 CPU / 48GiB（单位约定） |
| ASI / direct_llm 候选 | 128K = 131072 | 16K = 16384 | 一次完整程序生成＋真实执行；总墙钟30min，需同时约束生成与执行 | 4 CPU / 8GiB |
| HLE / 官方问答客户端 | 128K = 131072 | 16K = 16384 | 无工具；每题总墙钟30min，单HTTP600s及原重试另固定 | 共享客户端，模型服务另计 |

128K统一用于非Terminal项目，减少预算分支；HLE题目通常不需要长历史，但这里不靠裁掉图像或正式题干降低预算。真实输入长度需由固定tokenizer/processor验收。ASI若改选OpenCode，多轮输出候选8K、总context128K、总墙钟30min；原生100steps只作为收尾提示，固定代码未实际禁用下一轮工具，不能称100次硬限。它是另一条正式前择一路线，不能与direct_llm混报。

这些是较原草案更保守的**实验自选预算**：原草案非Terminal context为256K，SWE/HLE单次输出32K。缩减可能影响得分；统一用于该项Base、专家、合版，不能对低分模型追加预算。不能只改服务端共享最大长度就声称各客户端已经落实128K；原生不支持的限制需薄适配或按benchmark分块使用相应服务配置。任何超限失败保留在预期任务分母，不静默跳过。

## 显存估算及部署策略

- 固定权重张量共71,903,645,408B，约66.97GiB。全35B权重都需驻留；3B激活不等于3B权重显存。TP4仅权重均分约16.74GiB/卡，TP2约33.48GiB/卡，实际还有复制的视觉等模块。
- 固定config是30层linear attention＋10层full attention，full attention为2KV头、head_dim256、BF16。未分片常规full-attention KV为 `10 × 2(K/V) × 2(heads) × 256 × 2(bytes) = 20480 B/token`：128K约2.5GiB/序列，256K约5GiB/序列。不能套40层全attention估算，也不能漏掉linear state。
- TP4超过2个KV头，固定vLLM0.20.2会复制KV头，不能把上述KV总量直接除4：TP2/TP4每卡256K full-KV均约2.5GiB/序列。分页/混合cache padding、linear state、视觉特征、激活、通信与graph workspace还需计入；这些数字只作数量级推算，不能当实际vLLM显存回执。此前实际GPU识别为H100 80GB HBM3、81559MiB/卡（约79.65GiB），不按整80GiB计算硬余量。详见 [显存专项](agent_capacity_memory_review.md)。
- 正式服务优先一个TP4实例，BF16权重及BF16 KV；暂不依赖FP8/CPU offload/2卡训练＋2卡服务来保证排期。训练和评测分时。先验收2条同时活跃模型请求，再测4条；它是vLLM同时处理的sequence数，与同时存在的任务sandbox数不同。
- 候选 `gpu_memory_utilization=0.85`、chunked prefill、`max_num_batched_tokens=8192`、`max_num_seqs=2` 起步。8192是一次调度处理的token量，不是输入只能8192；只有实际启用chunked prefill且后端支持时，才可分块处理长输入。eager先用于验收，正式是否用graph依据测量。配置值仍需在实际0.20.2版本上验证。
- 仅把最大允许context从256K降至128K，不会让相同短输入本身更快，也不保证vLLM预留cache按比例减半；固定显存利用率时pool可能仍吃满既定预算。真正要测的是实际保留历史、输出长度、活跃请求和cache/调度策略，避免为名义节省无谓牺牲能力。
- 摘要会额外调用模型，也消耗上下文和时间。Terminal原生86016候选是“剩余历史估计token触发阈值”，不是历史总长度；仅提高阈值仍不能保证三阶段摘要总能容纳80K输出。需核固定源码、真实模板计数及超限恢复，必要时给辅助摘要独立较小输出预算并披露适配，不能裁官方题干。详见 [协议专项](agent_capacity_protocol_review.md)。

较短上下文落实最简方式是按预算分时使用相应服务硬上限：SWE65536，其他低预算32768，题定Terminal分块使用262144，所有对象一致；mini仅注册模型metadata不会强制短窗口，且没有原生历史摘要，不虚构已有自动压缩。SWE的8K输出需要预留输入空间，实际prompt最多57344token。原官方工具观察截断是10000字符、头尾各5000，继续保留，不能误称10000token。

## 承受显存与按时完成是两项验收

80共享主机可见128逻辑CPU、约2TiB RAM，不等于项目获独占资源；题定TB每任务32CPU/48GiB，模型排队也会消耗agent墙钟。不能从4卡显存推算TB有效并发或完工时间。最低TB矩阵为1335次；若平均15min，即便有效16并发也约20.9h，平均30min则约41.7h，均未含长尾，且16并发尚未获保障。这是情景算术，不是已测吞吐。

正式前最低验收：

1. 同一实际服务上的短文本、图像、各harness动作/观察/结束与实际请求参数通过。
2. 独立合成历史验证选定32K候选与题定Terminal的256K边界；如果某项正式前统一调整64K，再验其实际边界。输入＋输出合计、长工具结果及Terminus三阶段摘要不静默截断；不必为验收故意生成满80K废文本，但需覆盖接近总边界的执行及输出预算校验。
3. 2→4活跃请求，记录GPU峰值、KV容量/占用、抢占、tokens/s、TTFT、排队时间及超时；不是仅启动时通过就认定长请求成功。
4. 独立dev测任务CPU/RSS/I/O和模型等待，按有效吞吐冻结各项admission/调度策略，同项全部模型一致。

耗时还需与HTTP超时一致：生成满16K若只给600秒HTTP截止，平均decode至少约27.3token/s且还没计排队/prefill。生成满80K在50/100token/s时约27.3/13.7分钟，仅是算例；多轮与摘要会重复消耗。不能由“显存放得下”推导“单次/全矩阵按时完成”。

训练窗口根据轨迹实测另议，尤其SWE几乎不能整条装进8K；不把上述推理输出max_tokens用于直接截断SFT标签。窗口保留必要任务/工具上下文和正确loss mask，不简单截掉动作依赖的观察。推理窗口能力不等同同长度反向传播可行。
